# 주요 결정과 이유

다음은 실제 구현 과정에서 채택한 판단을 공개용으로 요약한 내용입니다. 제품 기획의 승인과 기능 검증의 완료는 따로 관리합니다.

## 미리보기와 출력을 같은 렌더러로 그린다

문구 줄바꿈, 회전, 컷 잘림을 화면과 다운로드에서 각각 구현하면 결과가 어긋나기 쉽습니다. Canvas2D 공통 렌더러를 두고 같은 문서를 두 해상도에 그리도록 했습니다. 실제 다운로드 PNG를 다시 디코딩해 카드 캔버스와 모든 RGBA 채널을 비교합니다.

이 선택은 출력 일관성을 높이는 대신, 선택 표시·손잡이·키보드 조작을 별도로 구현해야 하는 부담을 남깁니다. 그림 자체와 편집용 조작 UI를 분리해 다운로드에 선택 테두리가 섞이지 않게 했습니다.

## 내용은 공유하고 배치는 비율마다 보존한다

한 장의 카드를 8개 비율로 바꿀 때 내용까지 복제하면 문구 수정이 여러 사본으로 흩어집니다. 요소 내용과 비율별 배치를 분리했습니다. 글이나 색은 공유하고 위치·크기·회전은 비율마다 보존합니다.

모든 비율에서 자동으로 완벽한 구도를 만들겠다고 약속하지 않습니다. 사용자가 비율별로 구도를 조정하고 다시 돌아왔을 때 그 배치를 유지하는 쪽을 택했습니다.

## 잘못된 입력에서는 기존 작업을 보존한다

외부 파일을 먼저 현재 문서에 적용한 뒤 오류를 처리하는 방식은 피했습니다. 후보 문서와 이미지가 검증·렌더링된 뒤에만 현재 상태를 교체하고, JSON 묶음도 전부 유효할 때 단일 트랜잭션으로 저장합니다.

실제 실패를 수정한 전후 근거와 검사의 절차 오류는 구분합니다. 검사 실패가 나타났다는 이유만으로 제품 결함을 만들거나, 재검이 통과했다는 이유로 최초 실패 기록을 삭제하지 않습니다.

## 브라우저 편집기로 먼저 완성한다

로그인·결제·외부 AI를 먼저 연결하면 편집 동작과 서비스 의존성의 문제를 나누기 어렵습니다. 현재 공개본은 정적 앱과 IndexedDB로 이미지 입력·문구 편집·템플릿·출력까지 확인합니다. Node·npm의 고정 환경과 단일 잠금 파일을 사용해 설치와 검사를 재현할 수 있게 했습니다.

계정 저장, 실제 공동 작업 권한과 AI 처리는 이후 서버 경계에서 검증합니다. 읽기 전용 표시 화면이나 결과 파일 불러오기를 서버 권한·AI 연동 완료의 증거로 쓰지 않습니다.

## 자원과 직접 조작을 중심으로 UI를 줄인다

반복적인 소개·사용법 문구와 중복 저장 버튼을 줄이고, 자원 폴더·레이어·카드·도구를 중심으로 배치했습니다. 모바일은 편집 화면을 유지하면서 필요한 도구를 펼치고, 넓은 화면은 카드와 도구를 함께 봅니다.

레이어와 카드에서 같은 대상을 선택할 수 있고, 문구는 화면에서 편집할 수 있습니다. 숨김·잠금·그룹 상태는 레이어에서 확인하고 세부 메뉴로 조정합니다. 모양 선택기는 설명 문구 대신 실제 렌더링 경로를 축소해 보여줍니다.

## 정규형으로 추가하고 자유롭게 변형한다

이전 기본 도형은 컷 폭과 문구용 높이 비율을 함께 사용해 납작하게 추가됐습니다. 신규 도형은 픽셀 기준 정사각형·원·정삼각형·마름모로 계산하고, 추가 후에는 가로·세로를 독립적으로 바꿀 수 있게 했습니다.

정삼각형은 외곽선의 안쪽 여백까지 고려해 실제 세 변을 맞춥니다. 이미 저장된 작품의 모양을 바꾸지 않도록 렌더러와 이전 배치는 유지하고 새 생성 기본값만 변경했습니다. 손잡이의 최소 조작 영역과 작품의 최소 크기도 분리했습니다.

## 공개 저장소는 원본에서만 생성한다

구현·기획·검증의 비공개 원본에서 공개 가능한 코드와 요약 문서를 선별합니다. 공개본의 파일을 직접 고치거나 그 변경을 원본으로 가져오지 않습니다. 공개 수정도 비공개 원본에서 시작해 내보내기·검수 후 반영합니다.

이 구조는 과거 비공개 기록을 그대로 공개 이력으로 옮기는 일을 방지합니다. 공개 포트폴리오는 검토된 스냅샷이며, 공개 이력만으로 전체 개발 대화나 내부 운영 기록을 재구성할 수 있게 만들지 않습니다.

# 정적 빌드와 공개 사본

현재 [공개 앱](https://jjal-card-studio-three.vercel.app/)은 계정 없이 사용하는 정적 편집기다. 서버 계정·AI·결제 기능이 있는 정식 서비스 출시와 구분한다. Public 저장소 내보내기는 공개 소스 제출을 위한 절차이며 앱을 새로 배포하는 작업과 별개다.

## 로컬 빌드

Node 24 / npm 11 환경에서 잠금 파일로 설치하고 검사한다.

```sh
npm ci --ignore-scripts
npm run check
```

검사의 마지막 단계가 `apps/demo/dist`를 만든다. 빌드만 다시 할 때는 `npm run build`, 로컬 결과를 볼 때는 `npm run preview`를 사용한다. Vite의 source map 출력은 비활성화되어 있다.

`npm run release:prepare`는 기존 빌드와 권리 고지를 로컬 `.vercel/output`에 패키징한다. 네트워크 호출·업로드·기존 출력 삭제를 하지 않는다. 누락된 index, source map, 심볼릭 링크와 경계 밖 경로를 거부하며 기존 출력이 있으면 실패한다. 배포 계정·프로젝트 연결 정보는 공개 소스에 포함하지 않는다.

## Private → Public

원본 두 저장소는 Private에 둔다. 공개용으로 선별한 실행 코드·합성 입력·문서·그림만 새 Public 사본으로 내보낸다. 공개 정본에서 직접 수정하거나 원본으로 역방향 병합하지 않는다. 내보낸 파일 목록·해시를 공개 명세로 남기며, 원시 로그·환경변수·계정 및 배포 식별자·원문 대화·사용자 파일은 제외한다.

공개 `main`은 GitHub의 브랜치 잠금을 사용해 읽기 전용으로 관리한다. 검증된 원본 발행 절차만 반영 중 잠금을 해제하고 성공·실패와 관계없이 종료 시 잠금을 복구한다. 공식 설정 항목은 [GitHub branch protection 문서](https://docs.github.com/en/rest/branches/branch-protection?apiVersion=2026-03-10#update-branch-protection)의 `lock_branch`를 따른다. 이 규칙은 공개 소스 수정의 경계를 정하며, 앱 사용자의 편집 권한 구현을 뜻하지 않는다.

이 공개 사본에는 자동 앱 배포 workflow를 두지 않는다. 원본의 수정·공개 내보내기·앱 배포는 각각 검증하고 기록한다. 공개 앱의 내용을 바꾸는 작업에는 별도 배포 절차가 필요하다.

## 확인한 범위

2026-10-24 공개 앱 검사는 PC와 Pixel 7 브라우저 에뮬레이션 각 9단계, 총 18단계를 통과했다. 여러 문구·자원의 독립 배치, 정규 도형·축별 조절, 템플릿 저장·새로고침 뒤 복원, PNG 4개와 편집 화면의 픽셀 일치를 확인했다.

같은 날 원본 로컬 검사의 673개 단위 검사·유일 9개 브라우저 사례·PNG 35개와는 실행 범위가 다르다. 과거 결과를 Public 사본에서 방금 다시 실행한 것으로 표현하지 않는다. 실제 휴대전화·Safari·다른 OS·서버 성능·운영 복구 시간·제품 전체 인수는 이 검사로 완료 처리하지 않는다.
